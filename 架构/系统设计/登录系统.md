### oauth2.0

### SSO (单点登录 single sign on)
> 技术架构核心是 “统一身份源 + 跨系统信任 + 会话管理”

1. 首次登录：
        用户 → 访问 SP1（如OA系统） → SP1 检测无本地会话 → 重定向到 IdP（统一认证中心）
        → 用户输入账号+人脸（IdP 完成身份校验） → IdP 生成 JWT 令牌（含用户ID、角色、有效期）
        → 重定向回 SP1，并携带 JWT → SP1 验证 JWT 签名（确认来自可信 IdP）
        → SP1 创建本地会话（避免频繁验证 JWT） → 允许用户访问 SP1
2. 注销：
       用户 → 在 SP1 发起注销 → SP1 销毁本地会话 → 调用 IdP 注销接口
       → IdP 销毁全局会话 → IdP 通知所有已登录的 SP（SP2/SP3）销毁各自本地会话
       → 所有 SP 系统均登出，用户再次访问需重新认证

3. 不同协议对应不同的场景：
       3.1. CAS(center auth service), 专为 “企业级单点登录” 设计的集中式认证协议，核心是 “一次性票据（Ticket）+ 强身份校验”，安全性极高，是企业内网 SSO 的标杆。
                  缺点： 协议较重：SP 接入需集成 CAS 客户端（SDK）。 不适合跨组织场景（无标准跨 IdP 互认机制）
       3.2. SAML。 专门为跨组织 / 政企提供认证。 跨组织的 SSO 的国际标准，核心是 “XML 格式的身份断言（SAML Assertion）”
                  缺点： 性能略低， 配置复杂：XML 格式繁琐，需专业人员配置（如断言规则、证书交换）
       3.3. OIDC（OpenID Connect）：移动端 / 前后端分离首选。 基于 OAuth2.0 的认证扩展协议（OAuth2.0 仅授权，OIDC 补全认证），核心是 “JWT 格式的 ID Token”。
                  缺点： 身份属性传递简单：ID Token默认仅含用户唯一标识，复杂属性需额外扩展。 无垮组织能力。
       3.4. JWT 自定义 SSO：小型场景快速落地。
                  缺点： 无token过期能力，需要自己维护过期黑名单。
